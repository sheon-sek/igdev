# igdev 0.3.0

Ignition 8.3.10 support. New checkouts default to 8.3.10; 8.3.8 stays supported.

Install or upgrade:

```sh
curl -fsSL https://github.com/sheon-sek/igdev/releases/latest/download/install.sh | bash
```

## Compatibility

No CLI Contract change (still Contract 2) and no new error codes. Existing checkouts keep
the version their `igdev.toml` names.

## New

- **Ignition 8.3.10 Core Catalog** is embedded beside 8.3.8: built-in modules, `system.*`
  functions and the Gateway REST plane, so `lookup`, `check` and module defaults know 8.3.10.
- **`igdev init` defaults to 8.3.10.** Help text and docs no longer hard-code a version.
- **Data volume version guard.** Before `up`, `ensure`, `restart`, `module install` and
  `check --all --gateway` start a Gateway, igdev reads the Ignition version recorded in the
  existing data volume. An older volume prints a note that the upgrade is one-way; a newer
  volume fails at once with `IGDEV_E_GATEWAY_UNHEALTHY`, naming both versions and how to
  recover, instead of a container restart loop and a wait timeout.
- **For maintainers:** the dev-only `cmd/igdev-catalog` generator produces Core Catalog data
  from a running Gateway. It is not part of the released binary.

## Changed

- The 8.3.8 built-in module table no longer lists the MongoDB connector, which the 8.3.8
  image does not ship. A contract that names it in a module whitelist now refers to a module
  the image does not have; remove that entry.

## Moving an existing checkout to 8.3.10

1. Set `[ignition].version = "8.3.10"` in `igdev.toml`.
2. Run `igdev setup`, then start the Gateway as usual.

The data volume upgrades in place and one way: going back to 8.3.8 needs a fresh volume
(`igdev cleanup`, or a Baseline taken on 8.3.8).
