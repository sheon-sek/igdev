# igdev 0.3.1

Fixes Gateway connections, module installation and resource cleanup after 0.3.0.

Install or upgrade:

```sh
curl -fsSL https://github.com/sheon-sek/igdev/releases/latest/download/install.sh | bash
```

## Compatibility

CLI Contract remains 2. No new error codes or exit levels. `doctor` adds Instance
inventory data, and `cleanup` adds the `--obsolete-images` option and its result field.
Ignition 8.3.10 remains the default; 8.3.8 stays supported.

## Fixed

- Gateway public addresses use automatic detection instead of pointing Designer at
  `localhost:8088`. To repair an existing checkout after upgrading, run `igdev setup`
  followed by `igdev gateway up`. No volume reset is needed.
- `gateway wait` and `gateway ensure` install staged modules missing from an existing
  Gateway, including modules staged after its data volume was created.
- Gateway status checks the Gateway service itself. Reusing an Instance reconciles
  missing, stopped or obsolete trial keepers without removing Gateway data.
- Cleanup inventories dangling Instance images, removes images by immutable ID,
  preserves shared or multi-tagged images, and retains Checkout Setup while the
  Instance still has Docker objects.
- Interrupted commands clean up registered temporary files and lookup containers
  before exiting. Temporary lookup containers carry ownership labels, and removal
  failures are reported.
- Human Gateway logs stream directly. Compose failure diagnostics and local CI log
  tails have bounded buffers.
- Corrupt Jython cache samples are bounded, and old private-module indexes expire.

## Added

- `igdev cleanup --obsolete-images` reclaims attributable old-version images while
  keeping the Instance, data volume, network, Checkout Setup and Consent record.
  Preview with `igdev cleanup --obsolete-images --dry-run`.
- `igdev doctor` reports Instances whose checkout is missing, using full Instance
  identities. The audit remains read-only.
- A shared lifecycle regression matrix and an opt-in real-Gateway soak cover resource
  ownership and cleanup. The soak refuses existing or nested checkouts and foreign
  Instances; RSS reporting retains the full-run peak.

Per-container resource limits and additional volume/build-cache observability remain
design work and are not implemented by this release.
